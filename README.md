# 光栅尺测试台

基于 .NET 8 的 WPF 桌面工程。打开 `GratingRuler.sln`，启动项目为 `GratingRuler`。没有第三方 NuGet 依赖。

## 构建

要求 Windows 和 .NET 8 SDK（包含 Windows Desktop 引用包），或具备 .NET 桌面开发工作负载的 Visual Studio 2022。

```powershell
dotnet build .\GratingRuler.sln -c Debug
```

输出：`GratingRuler/bin/Debug/net8.0-windows/GratingRuler.exe`。

### VS Code 启动

在 VS Code 中打开包含 `GratingRuler.sln` 的根目录。按 `Ctrl+Shift+D` 打开“运行和调试”，选择“光栅尺测试台”，点击绿色三角或按 `F5`；每次启动前会自动编译。`Ctrl+F5` 用于不调试启动，`Ctrl+Shift+B` 仅编译。配置位于 `.vscode/launch.json` 和 `.vscode/tasks.json`，需要 Microsoft C# 扩展。CMake Tools 的启动按钮不用于此 WPF 工程。

## 当前实现

- 五个页面切换、常驻设备状态栏、软件急停入口和版本时间栏。
- 工作台根据任务切换点位、边沿事件、连续样本表及读数标题。
- 参数页按被测对象筛选任务；速度与加速度测试适用于所有非 IO 类型，自动指定高速台，其他任务自动指定常规台；测试台只读显示。
- 动态往返采集使用触发间隔，不配置采样率；Z 相及 IO 测试提供采样／采集频率；静态噪声提供到位后的稳定时长及上电／断电状态配置。
- 动态 Rz 提供测试前 Z、Rx、Ry 姿态及独立的 Rz 角度轨迹参数，仍为待定任务，不允许锁定。
- 速度与加速度测试提供测量轴、基准数据来源、时间修正、过渡剔除及分阶段误差限值；基准选择位置计算时展开差分和平滑窗口。被测端固定为传感器自身计算输出。这里只保存分析配置，尚未执行数据计算或阶段识别。
- 支持格式校验、参数锁定及解锁；按被测类型和项目保留本次会话中的输入，保存草稿仍只保存当前项目。草稿版本为 2，兼容版本 1，恢复时重新推导测试台并忽略已取消字段。
- 参数草稿异步保存和恢复，文件位于 `%LOCALAPPDATA%/GratingRuler/recipe-draft.json`。保存不会自动锁定，恢复不会启动设备。
- 实验记录查询条件、日期范围检查和清除；当前/历史报警表。
- 表格虚拟化、按钮键盘焦点、表单关联标签和空数据占位。

当前是可编译的离线界面工程。未接入设备驱动、任务执行器、数据存储和报警服务；没有仿真采样或虚构测试结果。设备状态为未知或未连接，启动、停止、连接、使能、PTP、JOG、导出和报警确认均不可用。软件急停会明确提示“未发送”，不改变设备状态。

曲线区域目前只有网格与空态；记录查询尚无数据源，导出和会话详情未实现。参数锁定只表示界面草稿通过基本校验，不表示配方已满足硬件执行条件。现有初值不是设备推荐参数。

## 界面调整

在原方案基础上去掉顶栏副标题、装饰性信息和大块引导文案。页面采用标准表单、紧凑分组和表格；每个状态只在有用的位置显示。右栏收为 260 DIP，给业务区留出空间。原 SVG 保留为早期设计参考，以工程 XAML 为当前实现。

## 代码位置

| 路径 | 职责 |
| --- | --- |
| `GratingRuler/App.xaml.cs` | 创建并注入主 ViewModel，管理窗口生命周期 |
| `GratingRuler/Views/MainWindow.xaml` | 主窗口布局、导航与页面模板 |
| `GratingRuler/Views/Pages` | 五个业务页面 |
| `GratingRuler/Views/Controls` | 设备状态栏、按采集类型切换的记录表 |
| `GratingRuler/ViewModels` | 页面状态、参数联动、草稿保存与命令 |
| `GratingRuler/Models` | 任务目录、参数字段、记录类型 |
| `GratingRuler/Resources` | 共享颜色与控件样式 |
| `GratingRuler/Infrastructure` | 通知基类、命令与空态转换器 |

View 的 code-behind 仅初始化组件；设备逻辑不在界面中实现。未引入泛化服务框架或供应商品牌假设。
